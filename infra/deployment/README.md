# GraphClaw ECS Deployment Strategies

This directory defines the deployment strategy, health-check configuration, and ECS/CodeDeploy AppSpec generation for every GraphClaw service.

## Per-Service Strategy Choices

| Service | Strategy | min_healthy_percent | Rationale |
|---|---|---|---|
| `agent-runtime` | Rolling | 0% | Scale-to-zero service; brief downtime during deploy is acceptable. |
| `channel-gateway` | Rolling | 100% | Always-on; must maintain full inbound email/webhook capacity at all times. |
| `trigger-engine` | Rolling | 50% | Stateless workers; 50% capacity during rolling replace is sufficient. |
| `api-server` | Blue/Green | 100% | Public REST API; zero-downtime guarantee requires full blue/green swap. |

## Rolling Strategy

ECS replaces task instances one at a time (or in batches, bounded by `max_percent=200`).

- **Circuit breaker**: All rolling services enable the ECS Deployment Circuit Breaker. If the new revision fails to reach steady state, ECS automatically rolls back to the last stable task definition.
- **Health check**: Each service uses the `/healthz` path with a 10-second interval and a threshold of 2 consecutive successes. The ECS grace period equals `interval_seconds × unhealthy_threshold` (30 s by default).

## Blue/Green Strategy (`api-server`)

The `api-server` uses AWS CodeDeploy with the `CODE_DEPLOY` ECS controller type:

1. CodeDeploy launches a complete replacement ("green") task set behind a second ALB target group.
2. Traffic is shifted from the "blue" target group to the "green" one according to the deployment group's traffic-routing configuration (e.g. `AllAtOnce`, `Linear10PercentEvery1Minute`).
3. The original "blue" task set is drained and terminated after the configured wait time.
4. If any lifecycle hook (`BeforeInstall`, `AfterInstall`, `AfterAllowTestTraffic`, `BeforeAllowTraffic`, `AfterAllowTraffic`) fails or the canary test fails, CodeDeploy rolls back by shifting traffic back to "blue".

The AppSpec YAML for each deployment is generated by `generate_appspec_yaml()` in `ecs_deploy.py`.

## Zero-Downtime Guarantee

Zero downtime is achieved through a combination of:

1. **min_healthy_percent=100** on `channel-gateway` and `api-server` — ECS never terminates an old task before a new one passes health checks.
2. **Deployment circuit breaker** on all services — automatic rollback prevents a bad deploy from taking the service fully down.
3. **Blue/green** on `api-server` — traffic is only shifted once the green environment is fully healthy, providing an instant rollback path.
4. **ALB connection draining** — in-flight requests complete before a task is deregistered.

## Adding a New Service

1. Add an entry to `DEPLOYMENT_CONFIGS` in `models.py`.
2. Choose `RolloutStrategy.ROLLING` for stateless background workers or `RolloutStrategy.BLUE_GREEN` for public-facing APIs.
3. Set `min_healthy_percent=100` if the service must not lose capacity during deploy; `0` if scale-to-zero is acceptable.
4. Add the service to `infra/iam/roles.py` if it needs direct AWS API access.
