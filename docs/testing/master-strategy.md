## Test pyramid

| Layer | Name | graphclaw | cockpit | CI trigger |
|---|---|---|---|---|
| L1 | Unit | `tests/test_*/` — pytest, fakes, no I/O | `src/**/*.test.tsx` — Vitest + MSW | Every PR |
| L2 | Component | — | `src/**/*.test.tsx` — Vitest + RTL + `renderWithProviders` | Every PR |
| L3 | Contract | `tests/contract/` — schemathesis vs `/openapi.json` | `src/test/contract/` — MSW handlers vs `openapi.json` | Every PR |
| L4 | Integration | `tests/integration/` — pytest + httpx, real services, `--run-integration` | — | Every PR with sidecars |
| L5 | E2E | — | `e2e/specs/` — Playwright + full Docker stack | Every PR |
| L6 | Load | `tests/load/` — Locust | — | Manual + nightly |
| L7 | Agent Evals | `tests/agent_evals/` — YAML + real LLM + LLM-as-judge, `--run-evals` | — | Canary on PR (agent-path changes); full nightly |
| — | CLI | `tests/test_cli/` — Typer CliRunner | — | Every PR |
| — | Manual smoke | `scripts/api_smoke.py`, `scripts/chat_repl.py` | — | **NEVER in CI** |

---

## What each layer guarantees

**L1 Unit** — logic is correct in isolation. If a unit test passes, the function/class does what its signature promises. No I/O, no network, no database. Use fakes (FakeGraphStore, FakeStorageClient) rather than mocks for boundary types.

**L2 Component** — React components render without crashing, respond to user interactions correctly, match a11y expectations, don't silently discard props. MSW intercepts API calls so component tests never hit a real server.

**L3 Contract** — the backend OpenAPI spec and the frontend MSW handlers agree. If a contract test fails, the two repos have drifted — either the backend added/changed an endpoint or the frontend handler is stale. Catch this before E2E.

**L4 Integration** — multiple services work correctly together: GraphQL queries round-trip through Postgres+AGE, Redis pub/sub delivers events, MinIO stores and retrieves files. Uses real infrastructure. Tests are gated behind `--run-integration`; they do not run unless the Docker stack is up and passing a service precheck.

**L5 E2E** — the user experience is correct end-to-end: click in the browser, verify state in the database and object store. Uses the full Docker stack. Only one worker (backend rate-limit at 300 req/min/user).

**L6 Load** — the system meets throughput and latency budgets under sustained load. Target: P99 < 2000ms at 100 req/s. Run manually before releases and nightly on main.

**L7 Agent Evals** — the main orchestrator (betty) behaves correctly: delegates to skills rather than answering inline, constructs follow-ups correctly, refuses out-of-scope requests, maintains conversation context across turns. These are behavioral assertions against the real LLM. Non-deterministic; use canary (3–5 fast scenarios) on PRs that touch agent code, full suite nightly.

## Test ID scheme

Format: `GC-<L>-<DOM>-<W>-<NNN>`

| Field | Values |
|---|---|
| `<L>` | `U` unit · `C` component · `K` contract · `I` integration · `E` e2e · `L` load · `A` agent eval |
| `<DOM>` | 3–4 letter domain code (see registry) |
| `<W>` | Build wave: `W08`, `W12`, etc. |
| `<NNN>` | Zero-padded sequence within (L, DOM, W) |

Domain codes: `SCO` scoring · `STA` state · `INB` inbound · `TRG` triggers · `GRA` graph · `AUT` auth · `CHT` chat · `CAN` canvas · `MKT` marketplace · `A2A` · `MCP` · `SKL` skills · `API` api · `JNY` journey · `ORC` orchestrator · `CLI` cli · `INT` intelligence · `ADM` admin · `STG` settings · `INF` infra · `GWY` gateway · `WRK` workers · `LLM` llm

Registry: [test-id-registry.md](test-id-registry.md) — autogenerated from inventory files.

**Backfill policy**: every NEW test gets an ID. Legacy tests get IDs opportunistically when touched. Per-domain lint: warn until domain is fully backfilled, then error.

## File header convention

Every test file MUST start with a structured header block. Updating the test forces updating the header. CI lints this.

### Python

```python
"""
GC-I-API-W11-007 — Task lifecycle integration

Scenario: A user creates a task via POST /tasks. The system persists it to
the AGE graph and writes an audit row. Listing /tasks returns it.

PRD: docs/prd/03-task-management.md §AC-3.2.1, §AC-3.4.4
Build wave: W11
Layer: L4 Integration
Owner: backend-team
Last reviewed: 2026-05-04

Cases covered:
- Happy path: create → graph node exists → audit row exists
- Validation: missing goal_id returns 422
- Auth: missing token returns 401

Notes:
- Requires --run-integration flag and live Postgres+AGE+Redis+MinIO.
- Resets graph between cases via clean_graph autouse fixture.
"""
```

## Fixture conventions

### Backend (pytest)

- **Fakes over mocks**: Use `FakeGraphStore`, `FakeStorageClient`, `FakeSecretsClient` for boundary injection. Mocks (`unittest.mock.Mock`) only for third-party libraries with no fake equivalent.
- **Factories**: `tests/fixtures/factories.py` provides `make_task()`, `make_goal()`, `make_user()`, `make_resource()` with overridable defaults.
- **Clean graph**: `clean_graph` fixture in root `conftest.py` resets the AGE graph via Cypher `MATCH (n) DETACH DELETE n` after each integration test. Autouse for `tests/integration/`.
- **Service precheck**: `tests/integration_precheck.py` validates Postgres/AGE, Redis, MinIO before integration tests run. If any service is down, integration tests are collected but skipped (not failed).

### Frontend (Vitest)

- **`renderWithProviders`**: Always use this wrapper from `src/test/utils.tsx`. It sets up QueryClient (retry: false, gcTime: 0) + MemoryRouter + MSW. Never render components bare.
- **MSW handlers**: Add handlers to `src/test/handlers.ts`. Use `http.get/post/patch/delete` from `msw`. Every handler must reflect the real OpenAPI spec shape.
- **Fixture data**: `src/test/fixtures/` has typed TS objects. Import from there, never hardcode inline.

### E2E (Playwright)

- **Fixtures via `test.ts`**: Always import `test` from `e2e/fixtures/test.ts` (not `@playwright/test` directly). The merged fixture gives you `page`, `auth`, `db`, `minio`, `api`, `seed` in every test.
- **Seed manifest**: `seed.fixture.ts` runs `seed-all.ts` once before the suite and writes `e2e/seed/.seed-manifest.json`. Tests reference stable IDs from `manifest.*` rather than hardcoding.
- **Locators**: prefer `getByRole` → `getByText` → `getByTestId` → CSS selector (last resort).

## Scripts vs tests

The rule: **should this fail the build if it breaks?** Yes → pytest integration test. No → script in `scripts/` that never runs in CI.

`scripts/api_smoke.py` — prints raw JSON from a running API for human eyeballing. No assertions.
`scripts/chat_repl.py` — interactive REPL for testing the orchestrator manually.

If a script becomes important enough to gate releases, **promote it**: rewrite with assertions + fixtures → move to `tests/integration/` → delete the script.
